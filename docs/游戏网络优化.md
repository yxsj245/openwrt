# 游戏场景网络优化指南

> **适用分支**：通用分支（兼容性第一）  
> **目标**：在不影响通用场景稳定性的前提下，针对在线游戏（低延迟、低抖动）场景提供最大化的网络优化  
> **原则**：新增软件包均为 OpenWrt 官方仓库提供的成熟工具，不引入激进内核补丁或第三方闭源模块

> **2026-08-17 更新**：固件已用 QoSmate 同时取代 SQM 和原客户端限速插件。本文中 SQM 页面的旧操作截面仅作 CAKE 参数原理参考，实际配置请使用 **网络 → QoSmate**，并参见 [QoSmate 使用与迁移说明](qosmate.md)。

## 一、当前已有优化（已编译进固件）

以下优化项已在当前 `config-temp` 中启用，编译后自动生效：

### 1.1 QoSmate 智能队列与客户端限速

| 软件包 | 状态 | 作用 |
|--------|------|------|
| `qosmate` | ✅ 已启用 | CAKE/HFSC、DSCP 分类和客户端限速 |
| `luci-app-qosmate` | ✅ 已启用 | LuCI Web 管理界面 |
| `kmod-sched-cake` | ✅ 已启用 | CAKE 队列调度算法内核模块 |
| `kmod-sched-core` | ✅ 已启用 | tc 流量控制核心模块 |
| `kmod-ifb` | ✅ 已启用 | 中间功能块设备，SQM 入向整形依赖 |

**效果**：QoSmate 统一管理 CAKE 队列、DSCP 优先级和每客户端带宽上限，既抑制 bufferbloat（缓冲膨胀），也取代了原有的独立客户端限速插件。

### 1.2 nftables 软件流量分载

| 软件包 | 状态 | 作用 |
|--------|------|------|
| `kmod-nft-offload` | ✅ 已启用 | nftables 流量分载引擎 |

**效果**：将已建立连接的路由/NAT 转发从 CPU 逐包处理转移到快速路径，降低 CPU 使用率，减少转发延迟。与 firewall4（nftables）原生集成，无需额外配置。

> ⚠️ **与 SQM 的关系**：流量分载和 SQM 不可同时生效（分载会绕过 tc 队列）。默认情况下 firewall4 的流量分载与 SQM 互斥，用户可根据需要选择启用其一。游戏场景建议优先使用 SQM。

### 1.3 全锥型 NAT（NAT1 / Fullcone NAT）

| 软件包 | 状态 | 作用 |
|--------|------|------|
| `kmod-nft-fullcone` | ✅ 已启用 | 全锥型 NAT 内核模块 |
| `luci-app-fullconenat` | ✅ 已启用 | LuCI Web 管理界面 |

**效果**：将 NAT 类型从"对称型"（NAT4）提升为"全锥型"（NAT1），改善 P2P 联机匹配成功率和游戏主机的 NAT 类型检测。对 Switch/PS5/Xbox 的在线联机体验有明显帮助。

### 1.4 TCP BBR 拥塞控制

| 软件包 | 状态 | 作用 |
|--------|------|------|
| `kmod-tcp-bbr` | ✅ 已启用 | BBR 拥塞控制算法内核模块 |

**效果**：BBR 相比传统 CUBIC 算法在高延迟、有丢包的网络环境中显著提升吞吐量，减少 TCP 重传引起的延迟抖动。启用后需将系统默认拥塞控制算法切换为 `bbr`（见第三章 sysctl 配置）。

### 1.5 DNS 服务

| 软件包 | 状态 | 作用 |
|--------|------|------|
| `dnsmasq-full` | ✅ 已启用 | 增强版 DNS/DHCP 服务 |
| `luci-app-adguardhome` | ✅ 已启用 | AdGuardHome DNS 广告过滤 |

**效果**：dnsmasq-full 支持 DNSSEC、nftset、conntrack 等高级特性；AdGuardHome 在 DNS 层面过滤广告和跟踪器域名，减少不必要的 DNS 查询和广告流量。

### 1.6 内核级优化

| 配置项 | 状态 | 作用 |
|--------|------|------|

| `CONFIG_KERNEL_NF_CONNTRACK_TIMEOUT` | ✅ | 连接跟踪超时策略支持 |

## 二、通用分支推荐新增优化

以下两项为兼容性极高的成熟工具，建议在通用分支中编译进固件。

### 2.1 irqbalance（中断负载均衡）

| 属性 | 值 |
|------|-----|
| 软件包名 | `irqbalance` |
| LuCI 界面 | `luci-app-irqbalance`（可选） |
| 资源占用 | 很小（守护进程，< 5MB 内存） |
| 兼容性 | 所有多核 CPU，无已知副作用 |
| 官方仓库 | OpenWrt 官方自带 |

**作用**：在多核 CPU 上自动将网卡等硬件的中断请求（IRQ）均匀分配到各核心，避免所有中断集中在 CPU0 导致单核瓶颈。

**为什么通用分支需要**：x86 软路由通常 2-8 核，默认情况下网卡中断全部压在 CPU0 上。当网络流量大时，CPU0 的 softirq 占用可达 100%，而其他核心空闲，导致转发延迟增加。`irqbalance` 自动优化分配，无侵入性。

**启用方式**：安装后默认自动启动，无需手动配置。

### 2.2 ethtool（网卡诊断与调优工具）

| 属性 | 值 |
|------|-----|
| 软件包名 | `ethtool`（基础版）或 `ethtool-full`（完整版） |
| LuCI 界面 | 无（命令行工具） |
| 资源占用 | 极小（命令行工具，不驻留） |
| 兼容性 | 所有以太网卡 |
| 官方仓库 | OpenWrt 官方自带 |

**作用**：
- 查看网卡驱动版本、链路状态、速率协商信息
- 查看/调整网卡 Ring Buffer 大小
- 查看/调整中断合并（coalescing）参数
- 查看/调整硬件 offload 特性（TSO/GSO/GRO）
- 网卡硬件自检和统计信息

**为什么通用分支需要**：
- `ethtool` 是 Linux 网络调试的标配工具，安装后不占用运行资源
- 为后续硬件特定分支的 NIC 深度调优提供基础
- 排查网卡问题（掉线、协商速率异常）时必需

**建议安装 `ethtool` 基础版**，`ethtool-full` 增加了网卡固件刷写等高级功能，通用分支不需要。

## 三、CAKE 游戏场景参数参考（请在 QoSmate 配置）

以下配置无需额外软件包，在 LuCI → Network → SQM QoS 页面中修改即可。各参数均为 CAKE 算法社区长期验证的成熟选项。

### 3.1 核心参数

```
┌─ Basic Settings ─────────────────────────────┐
│ Interface:       wan (或 pppoe-wan)           │
│ Download:        实际带宽的 85%-90%            │
│ Upload:          实际带宽的 85%-90%            │
└──────────────────────────────────────────────┘

┌─ Queue Discipline ───────────────────────────┐
│ Queueing Discipline:  cake                    │
│ Queue Setup Script:   layer_cake.qos          │
│ Advanced:             ✅ 勾选                  │
│  ┌─ Advanced Options ────────────────────┐    │
│  │ Ingress (download):                   │    │
│  │   nat ingress diffserv8 dual-dsthost  │    │
│  │ Egress (upload):                      │    │
│  │   nat ack-filter diffserv8 dual-srchost│   │
│  └───────────────────────────────────────┘    │
└──────────────────────────────────────────────┘

┌─ Link Layer Adaptation ──────────────────────┐
│ Link Layer:         根据链路类型选择            │
│  - 以太网/光纤:     ethernet, overhead 44      │
│  - PPPoE (VDSL):    ethernet, overhead 26/34  │
│  - DOCSIS (Cable):  ethernet, overhead 22     │
└──────────────────────────────────────────────┘
```

### 3.2 参数说明

| 参数 | 位置 | 作用 |
|------|------|------|
| `nat` | iqdisc/eqdisc | 利用内核 NAT 信息区分内网主机，实现**每主机公平**而非仅每流公平 |
| `ingress` | iqdisc | 入向整形模式，让下载方向带宽控制更贴近真实瓶颈 |
| `ack-filter` | eqdisc | 过滤冗余 TCP ACK 包，节省上传带宽（非对称宽带优势明显） |
| `diffserv8` | iqdisc/eqdisc | 8 级 DSCP 差分服务，相比默认 `diffserv4` 更细粒度优先级 |
| `dual-srchost` | eqdisc | 上传方向：同时按源主机和流做双维度隔离 |
| `dual-dsthost` | iqdisc | 下载方向：同时按目标主机和流做双维度隔离 |
| `layer_cake.qos` | script | Layer Cake 模式，基于 DSCP 做优先级区分 |

### 3.3 带宽限制建议

带宽限制值应设为**实际测速结果的 85%-90%**，让路由器的 SQM 队列成为瓶颈控制点，而非上游 ISP 设备的不可控大缓存。

```
示例：
  实际测速：500Mbps ↓ / 50Mbps ↑
  建议设置：450Mbps ↓ / 42Mbps ↑
```

## 四、sysctl 内核参数推荐配置

以下配置为通用兼容性参数，直接写入 `/etc/sysctl.d/10-gaming.conf` 即可生效。不会降低非游戏场景的吞吐量。

```ini
# ============================================================
# 游戏场景通用内核优化（兼容性优先）
# 适用: OpenWrt 通用分支，不依赖特定硬件
# ============================================================

# --- TCP 拥塞控制 ---
# 启用 BBR（需 kmod-tcp-bbr 已加载）
net.ipv4.tcp_congestion_control = bbr
# 默认队列算法（配合 CAKE 使用）
net.core.default_qdisc = fq_codel

# --- TCP 低延迟选项 ---
# 空闲后不进入慢启动（避免游戏间隔后突发降速）
net.ipv4.tcp_slow_start_after_idle = 0
# 启用 TCP Fast Open（减少连接建立 RTT）
net.ipv4.tcp_fastopen = 3

# --- UDP 缓冲区（游戏以 UDP 小包为主） ---
# 默认接收缓冲区 128KB（小缓冲 = 低排队延迟）
net.core.rmem_default = 131072
# 默认发送缓冲区 128KB
net.core.wmem_default = 131072

# --- 入向包队列 ---
# 增大每 CPU 入向包队列（应对突发小包）
net.core.netdev_max_backlog = 10000

# --- 连接跟踪优化 ---
# 缩短 UDP 超时（游戏心跳包通常 < 30s 间隔）
net.netfilter.nf_conntrack_udp_timeout = 30
net.netfilter.nf_conntrack_udp_timeout_stream = 60
```

> ⚠️ 以下参数**不加入通用分支**，因为它们为吞吐量优先或激进配置，可能影响非游戏场景。硬件特定分支可按需启用：
> - `net.core.rmem_max` / `wmem_max`（大缓冲 = 高吞吐，与游戏低延迟理念冲突）
> - `net.ipv4.tcp_tw_reuse = 1`（快速回收 TIME_WAIT，有极低概率的端口复用冲突）
> - `net.ipv4.tcp_notsent_lowat`（强制低水位推送，增加 CPU 开销）

## 五、推荐实施步骤

### Step 1：修改 config-temp，新增软件包

在 `config-temp` 中启用以下两项（可选启用 LuCI 界面）：

```diff
-# CONFIG_PACKAGE_ethtool is not set
+CONFIG_PACKAGE_ethtool=y

-# CONFIG_PACKAGE_irqbalance is not set
+CONFIG_PACKAGE_irqbalance=y

-# CONFIG_PACKAGE_luci-app-irqbalance is not set
+CONFIG_PACKAGE_luci-app-irqbalance=y    # 可选，提供 LuCI 管理界面
```

### Step 2：编译并升级固件

```
make defconfig && make -j$(nproc)
```

### Step 3：首次启动后手动配置

1. **QoSmate**：LuCI → 网络 → QoSmate → 核对 WAN 设备和上下行带宽
2. **sysctl**：将第四章配置写入 `/etc/sysctl.d/10-gaming.conf`，执行 `sysctl -p /etc/sysctl.d/10-gaming.conf`
3. **Fullcone NAT**：LuCI → Network → Fullcone NAT → 按需开启各区域
4. **BBR**：确认 `sysctl net.ipv4.tcp_congestion_control` 输出为 `bbr`

## 六、仅记录：硬件特定分支预留优化

以下优化项**不在通用分支中实现**，记录于此供按硬件创建分支时参考：

| 优化项 | 适用场景 | 通用分支不做的原因 |
|--------|----------|-------------------|
| NIC offload 调优（禁用 TSO/GSO/GRO） | 确定网卡型号后针对性调整 | 不同网卡驱动行为差异大，盲目关闭可能降低吞吐量 |
| 手动 IRQ 亲和性绑定 | 明确 CPU 核心数后精确绑定 | `irqbalance` 自动分配已足够；手动绑定需知道中断号 |
| CPU 性能模式 (`performance` governor) | 确认散热充足后锁定高频 | 部分被动散热设备可能过热 |
| SmartDNS 并发查询 | 需要 DNS 优选加速 | 增加配置复杂度，dnsmasq-full 已满足基本需求 |
| UPnP（miniupnpd） | 有游戏主机的家庭 | 安全风险（任意内网设备可开放端口），建议用户按需安装 |
| VPN 协议优化（WireGuard MTU 等） | 通过 VPN 玩外服游戏 | 通用分支不预装 VPN |
| WiFi 高级调优（AQL、airtime fairness） | 无线设备玩游戏 | 依赖 WiFi 芯片型号，且 SQM 已覆盖有线侧 |
