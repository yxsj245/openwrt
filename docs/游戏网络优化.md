# 游戏场景网络优化指南

> **适用分支**：J6412 + i226-V 硬件定制分支  
> **目标**：针对 Intel Elkhart Lake J6412 四核 + 4×Intel i226-V 2.5G 网卡硬件组合，提供最大化的低延迟网络优化  
> **原则**：新增软件包均为 OpenWrt 官方仓库提供的成熟工具，不引入激进内核补丁或第三方闭源模块

> **2026-08-17 更新**：固件已用 QoSmate 同时取代 SQM 和原客户端限速插件。本文中 SQM 页面的旧操作截面仅作 CAKE 参数原理参考，实际配置请使用 **网络 → QoSmate**，并参见 [QoSmate 使用与迁移说明](qosmate.md)。

|--------|------|------|

## 二、基础优化工具（已编译进固件）

以下两项为兼容性极高的成熟工具，已在本分支中编译进固件。

### 2.1 irqbalance（中断负载均衡）

| 属性 | 值 |
|------|-----|
| 软件包名 | `irqbalance` |
| LuCI 界面 | `luci-app-irqbalance`（可选） |
| 资源占用 | 很小（守护进程，< 5MB 内存） |
| 兼容性 | 所有多核 CPU，无已知副作用 |
| 官方仓库 | OpenWrt 官方自带 |

**作用**：在多核 CPU 上自动将网卡等硬件的中断请求（IRQ）均匀分配到各核心，避免所有中断集中在 CPU0 导致单核瓶颈。

**为什么本分支需要**：x86 软路由通常 2-8 核，默认情况下网卡中断全部压在 CPU0 上。本硬件 J6412 为 4 核 CPU，搭配 4×i226-V 网卡会产生 16+ 个 MSI-X 中断向量。`irqbalance` 自动优化分配，无侵入性。同时 `irq-affinity` 脚本提供针对 i226-V 的精确 IRQ-CPU 绑定（跳过 CPU0）。

**启用方式**：安装后默认自动启动，无需手动配置。

### 2.2 ethtool（网卡诊断与调优工具）

| 属性 | 值 |
|------|-----|
| 软件包名 | `ethtool`（基础版）或 `ethtool-full`（完整版） |
| LuCI 界面 | 无（命令行工具） |
| 资源占用 | 极小（命令行工具，不驻留） |
| 兼容性 | 所有以太网卡 |
| 官方仓库 | OpenWrt 官方自带 |

**作用**：
- 查看网卡驱动版本、链路状态、速率协商信息
- 查看/调整网卡 Ring Buffer 大小
- 查看/调整中断合并（coalescing）参数
- 查看/调整硬件 offload 特性（TSO/GSO/GRO）
- 网卡硬件自检和统计信息

**为什么本分支需要**：
- `ethtool` 是 Linux 网络调试的标配工具，也是 `nic-tuning-gaming` 包的依赖
- 为 i226-V 网卡的深度调优提供基础工具
- 排查网卡问题（掉线、协商速率异常）时必需

**建议安装 `ethtool` 基础版**，`ethtool-full` 增加了网卡固件刷写等高级功能，本分支不需要。

### 2.3 UPnP 端口映射（miniupnpd）

| 属性 | 值 |
|------|-----|
| 软件包名 | `miniupnpd-nftables` |
| LuCI 界面 | `luci-app-upnp` |
| 资源占用 | 极小（守护进程，< 10MB 内存） |
| 兼容性 | 需要 nftables（firewall4） |
| 官方仓库 | OpenWrt packages feed |

**作用**：允许局域网内的游戏主机（Switch/PS5/Xbox/PC）自动请求路由器开放端口，改善 P2P 联机和语音聊天的 NAT 穿透成功率。

**为什么本分支需要**：i226-V + J6412 为 4 口 2.5G 软路由，典型场景为家庭/小型工作室网关，多台游戏主机需要 UPnP 端口映射。

**安全提醒**：UPnP 允许任意内网设备开放端口，存在安全风险。建议仅在信任的内网环境启用，并通过 LuCI 界面限制允许使用 UPnP 的设备范围。

## 三、i226-V 网卡硬件调优详情

以下调优参数由 `nic-tuning-gaming` 包的 `nic-tuning` 脚本在启动时自动应用。脚本仅识别 PCI ID `8086:125c`（Intel i226-V）时执行。

### 3.1 ethtool 调优参数

| 参数 | 命令 | 值 | 原因 |
|------|------|-----|------|
| 多队列 (RSS) | `ethtool -L $iface combined 4` | 4 combined | J6412 有 4 核，每网卡 4 队列匹配 |
| 中断合并自适应 | `ethtool -C $iface adaptive-rx off adaptive-tx off` | 关闭 | 自适应会增加数 ms 延迟，游戏场景关掉 |
| RX 中断延迟 | `ethtool -C $iface rx-usecs 8` | 8 μs | 极低延迟，适合 FPS/竞技游戏 |
| TX 中断延迟 | `ethtool -C $iface tx-usecs 8` | 8 μs | 同上 |
| RX Ring Buffer | `ethtool -G $iface rx 256` | 256 | 小缓冲 = 低排队延迟 |
| TX Ring Buffer | `ethtool -G $iface tx 256` | 256 | 同上 |
| TSO | `ethtool -K $iface tso off` | 关闭 | 大包分段延迟，游戏小包不需要 |
| GSO | `ethtool -K $iface gso off` | 关闭 | 同上 |
| GRO | `ethtool -K $iface gro off` | 关闭 | 合并小包增加延迟 |

### 3.2 IRQ 亲和性策略

`irq-affinity` 脚本将 i226-V 网卡的 MSI-X 中断向量按轮询方式绑定到 CPU1-CPU3，跳过 CPU0：

```
端口1 IRQ → CPU1, CPU2, CPU3, CPU1
端口2 IRQ → CPU2, CPU3, CPU1, CPU2
端口3 IRQ → CPU3, CPU1, CPU2, CPU3
端口4 IRQ → CPU1, CPU2, CPU3, CPU1
```

**设计理由**：
- CPU0 保留给系统任务（定时器、内核进程），避免网络中断抢占
- 4 个端口 × 4 个 TxRx 队列 = 16 个中断向量，均匀分散到 3 个核心
- 轮询分配避免多端口同队列竞争同一核心

### 3.3 控制台菜单识别显示

`/usr/lib/console-menu/display.sh` 中增加了 i226-V 检测逻辑：物理终端登录时，如果检测到 i226-V 网卡，菜单会在版本信息下方显示：

```
  Hardware: Intel i226-V 2.5G detected
  NIC tuning: Low-latency gaming profile applied
```

仅在 PCI ID 完全匹配 `8086:125c` 时显示。

### 3.4 PCIe ASPM 建议

```bash
# 检查当前 ASPM 策略
cat /sys/module/pcie_aspm/parameters/policy

# 建议设为 performance（省电模式会让 PCIe 链路空闲降速，重新协商有延迟）
echo "performance" > /sys/module/pcie_aspm/parameters/policy
```

> ⚠️ ASPM 调优影响功耗和发热，J6412 是被动散热，如设 `performance` 请留意温度。

## 四、CAKE 游戏场景参数参考（请在 QoSmate 配置）

以下参数来自原 SQM 页面，保留用于说明 CAKE 配置原理。当前固件请在 LuCI → 网络 → QoSmate 中配置对应参数，具体操作参见 [QoSmate 使用与迁移说明](qosmate.md)。

### 4.1 核心参数

```
┌─ Basic Settings ─────────────────────────────┐
│ Interface:       wan (或 pppoe-wan)           │
│ Download:        实际带宽的 85%-90%            │
│ Upload:          实际带宽的 85%-90%            │
└──────────────────────────────────────────────┘

┌─ Queue Discipline ───────────────────────────┐
│ Queueing Discipline:  cake                    │
│ Queue Setup Script:   layer_cake.qos          │
│ Advanced:             ✅ 勾选                  │
│  ┌─ Advanced Options ────────────────────┐    │
│  │ Ingress (download):                   │    │
│  │   nat ingress diffserv8 dual-dsthost  │    │
│  │ Egress (upload):                      │    │
│  │   nat ack-filter diffserv8 dual-srchost│   │
│  └───────────────────────────────────────┘    │
└──────────────────────────────────────────────┘

┌─ Link Layer Adaptation ──────────────────────┐
│ Link Layer:         根据链路类型选择            │
│  - 以太网/光纤:     ethernet, overhead 44      │
│  - PPPoE (VDSL):    ethernet, overhead 26/34  │
│  - DOCSIS (Cable):  ethernet, overhead 22     │
└──────────────────────────────────────────────┘
```

### 4.2 参数说明

| 参数 | 位置 | 作用 |
|------|------|------|
| `nat` | iqdisc/eqdisc | 利用内核 NAT 信息区分内网主机，实现**每主机公平**而非仅每流公平 |
| `ingress` | iqdisc | 入向整形模式，让下载方向带宽控制更贴近真实瓶颈 |
| `ack-filter` | eqdisc | 过滤冗余 TCP ACK 包，节省上传带宽（非对称宽带优势明显） |
| `diffserv8` | iqdisc/eqdisc | 8 级 DSCP 差分服务，相比默认 `diffserv4` 更细粒度优先级 |
| `dual-srchost` | eqdisc | 上传方向：同时按源主机和流做双维度隔离 |
| `dual-dsthost` | iqdisc | 下载方向：同时按目标主机和流做双维度隔离 |
| `layer_cake.qos` | script | Layer Cake 模式，基于 DSCP 做优先级区分 |

### 4.3 带宽限制建议

带宽限制值应设为**实际测速结果的 85%-90%**，让路由器的 SQM 队列成为瓶颈控制点，而非上游 ISP 设备的不可控大缓存。

```
示例：
  实际测速：500Mbps ↓ / 50Mbps ↑
  建议设置：450Mbps ↓ / 42Mbps ↑
```

## 五、sysctl 内核参数推荐配置

以下配置为通用兼容性参数，直接写入 `/etc/sysctl.d/10-gaming.conf` 即可生效。不会降低非游戏场景的吞吐量。

```ini
# ============================================================
# 游戏场景通用内核优化（兼容性优先）
# 适用: OpenWrt 通用分支，不依赖特定硬件
# ============================================================

# --- TCP 拥塞控制 ---
# 启用 BBR（需 kmod-tcp-bbr 已加载）
net.ipv4.tcp_congestion_control = bbr
# 默认队列算法（配合 CAKE 使用）
net.core.default_qdisc = fq_codel

# --- TCP 低延迟选项 ---
# 空闲后不进入慢启动（避免游戏间隔后突发降速）
net.ipv4.tcp_slow_start_after_idle = 0
# 启用 TCP Fast Open（减少连接建立 RTT）
net.ipv4.tcp_fastopen = 3

# --- UDP 缓冲区（游戏以 UDP 小包为主） ---
# 默认接收缓冲区 128KB（小缓冲 = 低排队延迟）
net.core.rmem_default = 131072
# 默认发送缓冲区 128KB
net.core.wmem_default = 131072

# --- 连接跟踪优化 ---
# 缩短 UDP 超时（游戏心跳包通常 < 30s 间隔）
net.netfilter.nf_conntrack_udp_timeout = 30
net.netfilter.nf_conntrack_udp_timeout_stream = 60

# --- 2.5G 高速链路优化 ---
# 增大入向包队列（2.5G 突发更猛，i226-V 多队列并发）
net.core.netdev_max_backlog = 16384
# 允许软中断处理更多包再让出 CPU
net.core.netdev_budget = 600
```

> ⚠️ 以下参数**不加入通用分支**，因为它们为吞吐量优先或激进配置，可能影响非游戏场景。硬件特定分支可按需启用：
> - `net.core.rmem_max` / `wmem_max`（大缓冲 = 高吞吐，与游戏低延迟理念冲突）
> - `net.ipv4.tcp_tw_reuse = 1`（快速回收 TIME_WAIT，有极低概率的端口复用冲突）
> - `net.ipv4.tcp_notsent_lowat`（强制低水位推送，增加 CPU 开销）

## 六、推荐实施步骤

### Step 1：修改 config-temp，新增软件包

在 `config-temp` 中启用以下项（本分支已全部启用）：

```diff
+CONFIG_PACKAGE_ethtool=y
+CONFIG_PACKAGE_irqbalance=y
+CONFIG_PACKAGE_luci-app-irqbalance=y
+CONFIG_PACKAGE_nic-tuning-gaming=y
+CONFIG_PACKAGE_miniupnpd-nftables=y
+CONFIG_PACKAGE_luci-app-upnp=y
```

### Step 2：编译并升级固件

```
make defconfig && make -j$(nproc)
```

### Step 3：首次启动后手动配置

1. **QoSmate**：LuCI → 网络 → QoSmate → 核对 WAN 设备、上下行带宽及第四章所述 CAKE 参数
2. **sysctl**：将第五章配置写入 `/etc/sysctl.d/10-gaming.conf`，执行 `sysctl -p /etc/sysctl.d/10-gaming.conf`
3. **Fullcone NAT**：LuCI → Network → Fullcone NAT → 按需开启各区域
4. **BBR**：确认 `sysctl net.ipv4.tcp_congestion_control` 输出为 `bbr`
5. **UPnP**：LuCI → Services → UPnP → 配置允许的设备范围（建议白名单模式）
6. **NIC Tuning**：启动脚本自动运行，通过物理终端登录验证菜单是否显示 "NIC tuning: Low-latency gaming profile applied"
7. **IRQ Affinity**：SSH 执行 `cat /proc/interrupts | grep eth` 验证中断是否分散到 CPU1-3
